# 동선 결과 UI 설계 계약

2026-11-09. 사용자가 붙여 준 주간 회의록과 후속 지시를 기준으로, 일본 여행 초보자가 결과를 따라 읽을 수 있도록 개선한다. 재현되지 않은 하단 여백 문제는 사용자 지시로 제외한다.

## 범위와 인터페이스

- `demo.ts` 결과 영역, 순수 렌더러 `demo-route-render.ts`, 결과 전용 CSS와 회귀 검사.
- 입력은 기존 `DemoResult`의 하루 결과, 결과 기준 날짜·일차, 실제/예제 여부, 선택 장소와 장소 조회 함수다. 출력은 HTML이다.
- API DTO·파서·백엔드 최적화·지도 좌표·3단계 흐름·추가 추천 동작은 유지한다.

## 불변조건

1. 관광지 → 이용 역 → 응답의 역·노선 순서 → 이용 역 → 다음 관광지 순서로 표시한다. 장소 행의 지도 포커스 버튼과 선택 상태는 유지한다.
2. 관광지↔역 정보가 없으면 이동수단·시간·요금을 만들지 않고 미제공으로 표시한다.
3. 노선명으로 버스·철도·지하철을 추론하지 않는다. 명시적 `도보` 응답만 도보로 표시하고 나머지는 노선 이동과 원래 노선명을 보여준다.
4. 개별 단계 시간·요금·환승 횟수는 응답에 없으므로 표시하지 않는다. 단계 수에서 환승 횟수를 유도하지 않는다.
5. 누적 역 간 이동 시간을 장소 행에 표시한다. 서버 시각은 실제 관광지 도착 시각과 구별되는 참고값으로 표시한다. 개별 시각이 없으면 생략한다. 예제 시각은 생성하지 않는다.
6. 빈 경로만으로 같은 역이라고 판단하지 않는다. 양쪽 이용 역의 이름·좌표가 같을 때만 같은 이용 역이라고 표시한다. 역 간 0분이어도 관광지 사이 이동 없음으로 표시하지 않는다.
   같은 역인데 0이 아닌 시간·요금이 오면 서버 수치를 유지하고 경로 확인이 필요하다고 명시한다.
7. 시간·교통비가 역 간 기준임을 하루 및 여행 합계에 명시한다. 예제 출처를 유지한다.
8. 모든 외부 문자열과 식별자는 HTML 이스케이프한다. 상세 단계는 전체를 기본 표시한다.
9. 재계산 전 추가 장소·이전 결과·지연 응답 보호·일차 전환·선택적 추천은 유지한다.

## 수용 기준·테스트

- 다단계 철도명/명시적 도보/버스명이 순서대로 보이고, 임의 수단 분류나 환승 횟수는 없다.
- 빈 경로, 동명이역, 같은 역 0분, 장소 하나, 누락된 역·시각, 날짜 변경, 예제 데이터, 긴 이름과 HTML 문자를 검사한다.
- 기존 UI·API·지도 회귀 검사와 프로덕션 빌드를 통과한다.
- 브라우저에서 예제 결과, 지도 포커스, 일차 전환, 선택적 추천, 재계산 전 추가 장소를 확인한다. 제어된 공급자 응답으로 실제 프론트→FastAPI 결과 화면의 다단계 표시도 확인한다. Gemini 실호출은 보류한다.

## Opus 설계와 통합 판단

Claude Opus 설계 응답을 먼저 받은 뒤 구현했다. 제안 중 `빈 route → 같은 역`, `0분·0엔 → 이동 없음`, `단계 수−1 → 환승 횟수`는 실제 이동을 보장하지 않으므로 채택하지 않았다. 긴 경로도 중요한 단계를 숨기지 않도록 전체를 표시한다. 별도 순수 렌더러를 두어 결측값·이스케이프를 직접 검사한다.

주요 회귀 위험은 기존 시간 칩의 의미 변경, 역 정보 자리표시자의 노출, 상세 단계로 인한 패널 길이 증가, 지도 선택 버튼의 이벤트 계약이다. 외곽 배치·축소·높이 계산은 변경하지 않는다.

렌더러는 기존 파서가 검증한 역 좌표·방문 순서·구간 순서·합계를 전제로 한다. 없는 장소 ID나 잘못된 합계를 렌더러에서 별도로 보정하지 않는다. 이동 카드의 왼쪽 축은 장소 이름보다 방문 번호 아래에 연결되도록 배치한다.
