# 지도 이동 구간 색상 설계 계약

2026-11-09. 사용자 요청: 결과 목록과 마찬가지로 지도도 노선 이동은 파란 실선, 명시적 도보는 초록 점선으로 구분한다. Opus의 읽기 전용 설계 계약을 받은 뒤 구현했다.

## 변경 대상·인터페이스

- `demo-map-controller.ts`: `DemoMapView.routeSegments` 추가, 지도 선 재사용·수명 관리.
- `demo.ts`: 서버의 각 역 간 단계로 구간을 생성하고 SVG 대체 지도와 범례에도 반영.
- 결과 목록과 같은 파랑 `#3267d6`, 초록 `#258258` 사용. 지도 범례 스타일과 SDK·UI 회귀 검사 수정.
- 내부 구간은 `mode: transit | walking`, `from`, `to` 좌표로 구성한다. API DTO·백엔드·경로 알고리즘은 변경하지 않는다.

## 불변조건

1. `step.line === '도보'`일 때만 도보다. 관광지↔역 이동이나 노선 종류를 추정하지 않는다.
2. 실제 API 결과는 단계 하나당 독립적인 2점 선을 만든다. 단계·여정 사이 좌표가 떨어져 있어도 연결선을 만들지 않는다.
3. `routeSegments` 미정의는 기존 예제·레거시 동작, 빈 배열은 실제 결과에 경로가 없음을 뜻한다. 빈 배열을 관광지 연결선으로 대체하지 않는다.
4. 공통 `mapRoutePaths`가 SDK·SVG·좌표 투영에 같은 구간을 제공한다. 실제 API 화면은 `routeSegments`만 전달하고 기존 호출자의 `routePath`는 호환 목적으로만 수용한다. 양 끝 좌표가 같으면 지도에 점이나 선을 만들지 않는다.
5. 지도 객체·마커를 유지하고 선도 재사용한다. 선택만 바뀌면 선을 재생성하거나 경로를 다시 쓰거나 화면 범위를 재설정하지 않는다.
6. 재사용 슬롯의 수단이 바뀌면 아이콘·불투명도·색을 모두 복원한다. 남는 선은 경로를 비우고 숨기며 인증 실패·파괴 시 모두 분리한다.
7. 경로의 모든 끝점과 관광지를 지도 범위에 포함한다. 실제 도로·선로 모양이 아닌 역 좌표 간 참고선이라는 안내를 유지한다.
8. API 범례는 현재 결과에 존재하는 수단만 표시한다. 예제는 일반 방문 순서 선과 기존 예제 안내를 유지한다.

## 수용 기준·테스트·위험

- 서로 떨어진 노선/도보/노선 3단계가 각기 독립적인 선으로 그려진다. 도보 선은 초록 아이콘 반복, 노선 선은 파란 실선이다.
- 선택 변경, 일차 전환, 단계 감소, 경로 없음, 입력 단계 복귀, 인증 실패, destroy 및 비동기 로딩의 기존 회귀 검사를 통과한다.
- 재사용한 도보 선이 노선으로 바뀔 때 점선 아이콘이 남지 않는다. 빈 실제 경로에 관광지 직선이 생기지 않는다.
- 실제 브라우저에서 제어된 API 응답과 Google Maps SDK를 함께 확인한다. Gemini·크롤러 실호출이나 새 경로 조회는 하지 않는다.
- 위험: 지도 수단 색이 실제 경로 정확도를 암시할 수 있으므로 참고선 안내를 유지한다. Google SDK의 점선은 기본 선을 숨기고 반복 심벌을 표시하므로 심벌의 색·불투명도를 명시한다. SVG는 별도 dash 속성을 사용한다.

SDK 점선 구현은 [Google Maps 공식 예제](https://developers.google.com/maps/documentation/javascript/examples/overlay-symbol-dashed)의 기본 선 불투명도 0 및 반복 심벌 방식을 참고한다. 긴 경로도 구간 수에 따라 선을 재사용하며 임의로 단계를 잘라내지 않는다.
