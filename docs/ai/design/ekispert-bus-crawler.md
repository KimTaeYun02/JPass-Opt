# 기존 Ekispert 크롤러 버스 검증 계약

2026-11-14. 공식 API 도입 전에 기존 웹 크롤러 재사용 가능성을 검증한다.
Claude Opus를 현재 작업의 읽기 전용 하위 프로세스로 호출해 설계 계약을 받았다.

## 범위와 인터페이스

- 기존 `backend/app/crawling/ekispert.py`의 검색·추출 함수를 그대로 호출한다.
- 별도 CLI `backend/scripts/verify_ekispert_bus.py`와 합성 HTML 검사만 추가한다.
- 기본 실행은 브라우저·네트워크를 사용하지 않는다. 실제 조회는 `--live`가 필요하다.
- 실조회는 사용자가 지정한 운영사 포함 정류장 두 곳과 시간대가 있는 출발 시각을 받는다.
- 기존 API·최적화·프론트 응답 형식은 바꾸지 않는다. 버스 좌표 연결은 이번 검증 범위 밖이다.

## 불변조건

- 실행 한 번에 검색 시도 한 번. 주 프레임 문서의 403·429는 즉시 중단하고 재시도·우회하지 않는다. 부가 이미지 등의 거절은 사이트 전체 차단으로 분류하지 않는다.
- 전체 비동기 실행 제한은 90초이며 종료 시 작업과 브라우저를 정리한다.
- Google·Gemini·공식 Ekispert API를 호출하지 않고 키를 읽지 않는다.
- 검색 결과 양 끝의 전체 이름을 NFKC·공백 정규화 후 비교한다. 운영사 접미사는 제거하지 않는다.
- DOM의 지점/구간 교대 구조와 필수 시간·운임·노선 추출을 확인한다.
- 노선명의 `バス`는 이름 단서다. 공급자 교통수단 타입이나 정류장 고유 ID 검증으로 보고하지 않는다.
- 합성 fixture 통과는 현재 웹사이트 동작이나 실제 운행 증거가 아니다.
- 원본 크롤러의 URL 출력은 CLI에서 숨긴다. 응답 원문·예외 내용·인증 정보는 저장하지 않는다.

## 수용 기준과 테스트

1. 기본 실행과 잘못된 실조회 입력은 브라우저 없이 종료한다.
2. 실제 파서를 합성 DOM에 적용해 버스·도보·철도 혼합 순서, 운영사, 대안 순서, 미확인 시간·운임의 null을 확인한다.
3. 요청한 운영사가 다르거나 DOM 순서가 잘못되면 성공 단서로 인정하지 않는다.
4. 로컬 응답 대역으로 403·429에서 재시도 없이 종료하는지 확인한다.
5. 소규모 실조회 결과를 성공·차단·미확인으로 구분해 남긴다.

## 설계 조정과 회귀 위험

Opus의 제안 중 고정된 미검증 정류장 기본값·출발일 기본값·HTML 저장은 채택하지 않았다.
정확한 표기를 확인한 입력을 명시하도록 하고 원본 트래픽을 저장하지 않는다.
실조회는 사용자가 승인한 자동 검증 범위에서 실행했다.
파서 강화를 먼저 하면 정상 철도 결과가 버려질 수 있으므로 제품 코드는 수정하지 않는다.
기존 서비스는 모든 지점 좌표를 철도역 전용 HeartRails로 찾으므로 파싱 성공만으로 버스 연동 완료가 되지 않는다.
