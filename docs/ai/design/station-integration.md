# 계산 전 기준역 조회와 프론트 통합 계약

2026-11-05 Claude Opus 설계 검토를 바탕으로 정리한 구현 계약이다. 기존 Notion 확정 API를 바꾸지 않고 기준역 조회만 추가한다.

- 기준: 최신 병합된 `main`(`478e697`). 미병합 리팩터링 브랜치를 가져오거나 팀원의 경로 서비스·클라이언트·최적화 엔진을 수정하지 않는다.
- 신규 API: `POST /api/stations/resolve`. `days[{dayIndex,places[{googlePlaceId,location:{lat,lng}}]}]`을 받고 같은 ID·순서로 장소별 역 조회 결과를 반환한다.
- 일차는 1–7, 일차별 장소는 1–8개다. 입력 좌표는 유한한 숫자이며 문자열·불리언·정의되지 않은 필드는 HTTP 422로 거절한다. 일차와 일차 내 장소 ID는 중복될 수 없다.
- 기존 `get_nearest_stations(..., limit=1)`을 재사용한다. 같은 좌표는 요청 안에서만 한 번 조회한다. 공유 역을 가진 관광지는 별도 ID로 유지한다.
- 장소별 `ok/not_found/error`, nullable `station/reason`으로 일부 실패를 격리한다. 공급자 원문 오류는 응답에 포함하지 않는다. API 키·크롤링·동선 계산·Places 호출은 필요하지 않다.
- 프론트는 현재 일차의 기준역→Nearby와 위치 우선 조건을 적용한 Text Search를 실행하고 Google Place ID로 합친다. 장소가 없거나 태그가 없으면 필요한 호출만 생략한다. 부분 실패는 성공 결과와 경고를 유지한다.
- 검색 요청에서 서버 고정 필드 `languageCode`·`regionCode`를 제거한다. `textQueries:null, results:[]`는 추가 입력 안내로 표시한다. 구형 `clarificationQuestion` 응답도 수용한다.
- 명시적 버튼/Enter로만 호출한다. 일차·쿼리·조건 변경은 이전 초기 추천 응답 적용을 막고 HTTP를 취소한다. 한글 조합 입력 요소를 교체하지 않는다. 후보 캐시는 메모리에만 최대 20개이며 부분 실패는 캐시하지 않는다.
- 패키징된 프론트 런처·오프라인 보고서 경로는 유지한다. 서버 키는 프론트로 복사하지 않고 API 주소만 설정한다.

검증은 역 조회·LLM·Google·크롤러의 외부 경계만 대체한다. 실제 HTTP 어댑터→Vite 프록시→FastAPI 서비스→최적화 엔진 연결과 브라우저 화면 흐름을 확인한다. 키 없는 프론트 전체 테스트·빌드와 백엔드 계약 검사를 실행하고 최종 diff는 독립 검토한다. 미완성 시 PR을 갱신하지 않는다. 아직 없는 배포 서버나 실제 공급자 결과를 검증했다고 주장하지 않는다.
