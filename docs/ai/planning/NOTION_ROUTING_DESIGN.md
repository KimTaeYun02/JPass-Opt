# Notion 방문지 동선 프로토타입

## 현재 운영 기준 — 2026-10-14 DP 교체

역간 크롤러 `result.time`을 그대로 고정 비용으로 사용한다. 원본에 포함된 환승·대기는 유지하며,
최초 열차 대기·관광지 접근 도보·체류시간을 추가하지 않는다. 순서 계산에서는 다음 출발 시각을
연결하거나 재조회하지 않는다. 시간 최소, 동률이면 요금, 그다음 ID 코드 단위 순서다.
단일 최적 순서와 최대 3개 후보 모두 공통 Held–Karp DP를 사용한다.
기존 체류 일정과 공급자 재조회는 별도 명시 호출 기능이며 최적화에 자동 연결하지 않는다.

실제 20개 자료의 원본 time 기준 결과는 오다이바 → 네즈 신사 → 도쿄돔 → 메이지 신궁 →
에노시마, 143분·2,374엔이다. 과거의 대기 포함 160분 실험과 시간별 재조회는 이전 기준의 기록이다.
DP 전환 계약과 검증은 `HELD_KARP_MIGRATION.md`를 참조한다. 아래는 기존 데이터·어댑터 설계 기록이다.

## 범위와 설계 계약

출처는 `https://app.notion.com/p/3f76b39941c280709b39fbf09d433548`의
「참고 자료(블로그, paper 등등)」 두 JSON 및 「추가 가능한 필드」의 체류 후 재출발 설명이다.
원본의 7개 역간 조회 결과를 보존한다. 검색 날짜·시각은 원본에 없어 미확인이다.
2026-10-17 09:00 JST와 모든 방문지 체류 120분은 실행 예시의 가정이다.

- 장소 ID로 순서를 계산하고 이용 역은 별도 필드로 둔다.
- 방향별 고정 행렬에서 Held–Karp DP로 방문 순서를 계산한다. 5개 장소 80개 상태, 4개 장소 32개 상태다.
- 이동시간을 우선 최소화하고 동률이면 구간 독립결제 가정의 운임, 그다음 장소 ID 순서로 비교한다.
- 출발지와 도착지는 자유이며 출발지 복귀를 추가하지 않는다.
- 실제 스냅샷은 추정값보다 우선한다. 누락·역방향·같은 역인 두 장소 사이 도보를 임의로 채우지 않는다.
- 추정값은 호출자가 명시한 별도 입력으로만 받는다. 추정 구간 포함은 `candidate`, 전부 스냅샷이면 `unverified`다.
- 원본 데이터만으로는 16개/9개 장소 구간이 부족하므로 최적 순서를 출력하지 않는다.
- 최대 3개 후보를 로컬에서 만들고, 실제 공급자를 명시 연결한 경우 묶음당 첫 후보만 순차 조회한다.
- 재조회는 각 방문지의 체류시간을 더한 실제 요청 시각을 사용한다. 변경된 체류시간은 이후 요청 시각에 전파된다.
- 공급자 ID·출발역·도착역·정규화된 정확 시각·옵션 전체를 캐시 키로 삼는다.
- 장소 ID가 달라도 동일한 역간 조회 조건은 재사용 가능하며 방문지 자체를 합치지 않는다.
- 공급자 호출 한 번은 외부 경로 요청 최대 한 번이라는 어댑터 계약이다. 예산은 모든 묶음에서 공유한다.
- 캐시는 공급자 재사용 opt-in이 있을 때만 메모리에 보관하며 TTL 기본 5분이다. 실패/unknown은 보관하지 않는다.
- 동일 키 진행 중 요청은 합친다. 캐시 키에 UI 입력 버전을 넣지 않는다.
- 공급자 미연결·예산 부족·실패는 `unknown`으로 끝내고 이동시간 0으로 다음 요청을 진행하지 않는다.
- 도착+체류 일정은 역간 참고 일정이며 장소↔역 도보·영업시간·시각표 능력·패스 운임은 미확인이다. `verified`를 생성하지 않는다.

현재 실제 Ekispert 크롤러는 저장소에 없다. 공식 NAVITIME 상품 제약을 Ekispert 웹 크롤러의 제약으로 해석하지 않는다.
크롤러 파일 경로 또는 실행 인터페이스가 전달되면 어댑터를 연결해 실제 응답을 검증해야 한다.

## 변경 대상과 기존 동작 대비

이 작업 폴더는 Git 저장소가 아니다. 신규 파일은 전체가 추가 변경이며 기존 파일 변경은 다음과 같다.

- `web/src/route-optimizer.ts`: `RouteQuote.stations/source` 선택 필드 추가, `validateQuote` export,
  route 양끝 검사 대상을 역 필드로 분리, 행렬에 전체 quote 보존, 결과에 역과 출처 보존.
  기존 역명 키와 선택 필드 없는 호출은 유지한다.
- `web/src/route-candidates.ts`: 신규 장소·명시적 추정 모델, 누락 목록, 최대 3개 후보, 참고 체류 일정.
- `web/src/route-provider.ts`: 신규 공급자 인터페이스, 정확 키 메모리 캐시, 중복 요청 병합, 예산, 순차 재조회.
- `web/fixtures/notion-visits.json`: 신규 실제 원문 구간 데이터 두 묶음. 시간·운임·노선은 원문 그대로다.
- `web/scripts/demo-notion.mjs`: 신규 CLI. 원문만 실행하면 최적 결과 대신 데이터 부족 보고서.
- `web/tests/notion-routing.test.mjs`: 신규 의미 있는 회귀·동일 역·출처·시간·재조회·예산 테스트.
- `web/package.json`: `demo:notion` 스크립트 추가.
- `web/package.json` 및 `web/package-lock.json`: 네이티브 TypeScript 실행을 위한 Node 22.20 이상 요구 버전 기록.
- `web/README.md`: 새 CLI 입력·어댑터 계약·미확인 범위 안내 추가.
- `sample/notion-route-result.json`: 신규 실행 보고서.

기존 지도와 시간표 UI는 수정하지 않았다. `demo:route`의 기존 경로·비용 출력은 유지하고 DP 지표를 추가한다.

## 수용 기준 및 검증

기존 30개 테스트 유지, 두 묶음 데이터 합계 242분/3971엔과 38분/980엔 보존,
누락 목록 16개/9개, 명시 추정 행렬 120개/24개 비교, 같은 역 두 방문지 체류 각각 유지,
추정 1구간 이상 `candidate`, 전체 snapshot도 `unverified`, 동일 키 중복/재호출 1회,
예산0 호출0회, 실패 재조회 예산 차감, TTL 만료 재조회,
체류 수정 시 동일 조건 접두부 재사용 및 이후 시각 전파를 검증한다.

공급자는 테스트 대역으로 검증했다. 실제 경로 크롤링 및 유료 지도/API 호출은 0회다.
영업시간을 검사하거나 출입 가능 여부를 보장하지 않는다.

최종 실행 확인: `npm test` 41개 통과, `npm run build` 성공.
기본 CLI와 가상 `.mjs` 공급자 동적 로딩을 실제 자식 프로세스로 실행하는 테스트를 포함한다.
예산 2를 두 묶음에서 공유하는 경우 추가 호출은 첫 묶음 2회, 두 번째 묶음 0회이며 둘 다 unknown으로 끝난다.
독립 Opus 검토는 39개 테스트 시점에 PASS(조건부), BLOCKERS 없음이었다.
그 검토의 권고 중 출처 필수화, 잘못된 추정 입력 거절, 갱신 시간 합계·최적성 미재평가 표시,
CLI 통합 테스트와 Node 최소 버전을 추가하고 최종 41개 테스트 및 빌드를 다시 통과했다.
