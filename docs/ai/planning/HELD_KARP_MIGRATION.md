# 고정 역간 비용의 Held–Karp DP 교체

## 설계 계약

2026-10-14 사용자가 운영 완전탐색을 기본 Held–Karp DP로 교체하도록 요청했다.
목적함수는 크롤러의 `result.time` 합이며, 동률이면 `fee` 합과 JS 코드 단위 ID 순서로 비교한다.
첫·마지막 방문지는 자유이고, 모든 장소 ID를 한 번씩 방문하며 복귀 구간은 없다.
역↔관광지 도보·체류·최초 열차 대기를 별도로 더하지 않는다. 원본 time 안의 대기는 유지한다.
운영 범위는 기존 2~8개를 유지한다. 외부 경로 조회는 없다.

### 변경 대상과 인터페이스

- `route-dp.ts`: `(방문 집합, 마지막 지점)`의 상위 k개 경로를 보존하는 공통 DP. k는 1~3이다.
- `route-optimizer.ts`: `optimizeVisitOrder`와 추가된 `optimizeVisitOrders`가 DP를 호출한다.
- `route-candidates.ts`: 기존 장소·실측·추정 검사 후 같은 DP로 후보 배열을 생성한다.
- 실제 자료 데모·검증: 원본 time 사용. 과거 시간별 자료는 과거 선택 순서에 연결해 보존한다.
- 입력 fixture·공급자·일정 모델·지도 UI는 변경하지 않는다.

`RoutePlan`의 order/time/fee/legs는 유지한다. algorithm='held-karp', dpStates, dpTransitions를 추가하고
evaluatedOrders=0으로 남긴다. 실제 완전 순열 평가를 하지 않으므로 n!를 계산 횟수로 보고하지 않는다.
dpTransitions는 이전 상태와 마지막 지점 사이의 연결 수다. 각 연결에서 평가한 k개 후보 수는 별도이며
이 지표에 합산하지 않는다. rankCandidates는 기존 배열 반환 형식을 유지한다.

### 불변조건

- 완전한 방향별 비용표를 요구한다. 역방향·누락 비용과 같은 역인 서로 다른 관광지를 자동 추론하지 않는다.
- 검증된 비음수 안전 정수만 사용한다. 모든 가능한 경로의 시간·요금 최댓값을 BigInt로 추적해,
  최적 경로가 안전하더라도 다른 가능한 경로의 합계가 안전 범위를 넘으면 기존처럼 거절한다.
- ID를 기본 sort로 정렬한 순위를 경로 키로 사용해 입력 순서와 무관한 동점 처리를 유지한다.
- 같은 상태의 모든 경로는 같은 후속 선택지를 갖는다. 상위 k개 밖의 접두 경로는 같은 접미 경로를
  붙여도 앞선 k개 경로를 이길 수 없으므로 버려도 최종 상위 k개를 잃지 않는다.
- 경로는 불변 역참조로 보관하고 최종 선택 후 복원한다. 반환 legs는 원본과 다른 객체이며
  stations/source/route를 유지한다.
- 완전 행렬의 상태 수는 n·2^(n−1), 구조적 전이 수는 n·(n−1)·2^(n−2)다.

### Opus 설계 검토 반영과 조정

Opus는 공통 k-best DP, 정수 범위 검사, 원본 time 재검증, 독립 완전탐색 검증을 권고했다.
호환성을 위해 후보 반환을 wrapper로 바꾸라는 제안은 적용하지 않고 기존 배열을 유지했다.
검증용 DP 삭제 제안도 적용하지 않았다. 운영 DP를 복사하지 않은 별도 구현이며, 완전 순열 평가와
직접 합산도 계속 함께 검증하므로 운영 구현과 같은 함수를 비교하는 문제가 없다.
검증용 DP는 운영 코드에서 호출하지 않는다.
입력 순서별 누락 구간 오류의 순서는 기존 검증을 그대로 유지한다.

## 수용 기준과 회귀 검증

기존 동작과 동일한 순서·시간·요금·경로 데이터를 반환한다. 최대 3개 후보도 전체 순열의 직접
평가 결과와 정확히 일치해야 한다. 모든 동점·2개/8개 경계·입력 불변성·메타데이터·합계 오버플로를
검증한다. 기존 200개 무작위 행렬 검증에 상위 1~3개 후보를 검증하는 100개 행렬을 추가했다.

실제 자료의 상위 후보는 143분·2,374엔, 143분·2,561엔, 154분·2,572엔이다.
원본 time으로 변경하면서 첫 번째 순서가 바뀌었다. 새 최적 순서는 오다이바 → 네즈 신사 →
도쿄돔 → 메이지 신궁 → 에노시마다. 시간 최소 경로 두 개 중 요금이 작은 경로가 선택된다.

검증 명령: web 폴더에서 `npm test`, `npm run build`, `npm run verify:route`.
최종 구현 검증: 테스트 62개 통과, TypeScript와 Vite 빌드 성공, verify:route PASS.

Opus 최종 독립 검토: **VERDICT PASS, BLOCKERS 없음**. 공통 k-best DP의 접두 경로 교체 논리,
정렬된 ID 키의 동점 처리, BigInt 최댓값 검사의 기존 DFS와의 동치, 구조적 상태·전이 수를 확인했다.
실제 상위 3개 경로의 시간·요금을 제공된 원본 비용표에서 별도로 합산해 일치를 확인했다.
검토 원문은 `tmp/dp-migration-review-response.txt`, 최종 diff는 `tmp/dp-migration.diff`에 보존했다.

검토의 비차단 권고에는 7~8개 입력의 top-k 검사 확대와 테스트 보고서의 임시 출력 경로 분리가 있다.
현재 CLI 통합 테스트는 sample 보고서를 갱신하며, 검증 스크립트의 가중치 표는 원본 비용의
DP·완전탐색 일치를 검사한다. 원본 자료에서는 같은 경로가 시간·요금 모두 최소이므로 가중치에
따른 순서 전환을 검증하지 않는다. 별도의 수작업 사례와 과거 비용표가 가중치 전환을 검증한다.
기존 rankCandidates도 후보 수 1~3만 허용했으므로 해당 제한은 이번 교체로 추가된 변경이 아니다.

## 범위

고정된 비용표에서의 정확한 최적 경로다. 시각별 재최적화·영업시간·관광지 도보·패스 할인·숙소와
여러 날 배분은 이번 교체에 포함하지 않는다. 지도 제출 UI는 입력 요약 기능이며, 이번 변경은
경로 계산 모듈과 CLI에 적용된다.
