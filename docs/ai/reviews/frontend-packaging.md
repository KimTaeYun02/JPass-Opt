# 프론트 패키징 검증 기록

검증일: 2026-10-28. 대상: `origin/main`의 `b72b820`에서 분리한 `feat/frontend-demo`.

## 실제 실행한 검사

- 격리된 새 worktree의 `web/`에서 `npm ci --no-audit --no-fund` 성공. 원래 작업 폴더의 `node_modules`·`.env.local`은 복사하지 않음.
- `npm test`: **116/116 통과**, 실패·건너뜀 0. 기존 110개와 패키징 검사 6개.
- `npm run build`: TypeScript와 Vite 빌드 성공. `dist/index.html`·`dist/demo.html` 생성. Maps 키 없이 실행.
- PowerShell 도우미를 공백이 있는 다른 이름의 임시 폴더로 복사하고, 무관한 cwd에서 실제 호출. 백엔드·의존성 없이 `-ValidateOnly` 계획 확인. Vite 대역 Node 프로세스로 실제 인자·cwd·API 환경 전달과 호출자 환경 복원 확인. 누락 의존성·프로세스 종료 실패·잘못된 원점 URL 오류 확인.
- Vite의 기본 프록시, `.env.local`, 실행 환경의 우선순위, 두 HTML 입력 확인.
- 세 JavaScript CLI를 별도 임시 복사본에서 실행해 JSON·Markdown이 프론트 `.local-run/reports/`에만 생성되는지 확인. 실제 공급자 호출 없음.

최초 패키징 검사에서 `Get-Command node`가 여러 실행 경로를 반환하는 환경의 실행 실패를 발견했습니다. 첫 실행 파일을 명시적으로 선택하도록 수정한 뒤 전체 검사를 다시 통과했습니다.

## 변경 범위

프론트 소스는 기존 작업 폴더에서 보존해 포함했습니다. 이번 정리의 코드 변경은 프론트 실행 도우미·오프라인 보고서 저장 경로·그 회귀 검사에 한정합니다. UI·API DTO·알고리즘은 변경하지 않았습니다. 백엔드의 미병합 7개 커밋, 로컬 `route_service.py` 변경과 `contract_checks/`는 포함하지 않습니다. 기존 백엔드 checkout을 전환·초기화하지 않았습니다.

## 한계와 후속 확인

브라우저 접근 거부를 우회하지 않았습니다. 실제 화면 배치·포커스·IME·Google 마커 클릭·프록시 HTTP 왕복·Google/Gemini·크롤러 전체 연동은 미검증입니다. 백엔드 키는 별도 설정이 필요합니다. main에는 FastAPI 백엔드가 없으므로 API 모드에는 별도 `feat/backend-api` 서버가 필요합니다. CI는 추가하지 않았으며 CI 통과를 주장하지 않습니다.

## Git·문서 점검

새 파일 75개의 포함 범위가 `web/`·`docs/ai/`·루트 README로 한정됨을 확인했습니다. 상대 파일 링크 누락 0개, 비밀 패턴·개인 PC 절대 경로 발견 0개입니다. 기존 프론트 소스·픽스처·공개 자산·기존 테스트는 원본과 텍스트가 동일하며 `api-fixtures.mjs`의 마지막 빈 줄만 정리했습니다. 키·의존성·빌드·보고서가 ignore되는지, `.env.example`이 포함되는지 확인했고 `git diff --cached --check`도 통과했습니다. PR 전 원격을 다시 fetch해 main과 백엔드 기준 커밋에 추가 변경이 없음을 확인했습니다.

## 독립 검토 상태

Claude Opus 사전 설계 검토는 받았으며, 소스와 맞지 않는 제안은 [채택한 설계 계약](../design/frontend-packaging.md)에 판단 근거를 남겼습니다.

**최종 독립 정적 검토는 미완료입니다.** 첫 최종 검토 호출이 결과 없이 대기해 종료한 뒤, 핵심 변경과 실행 근거로 범위를 줄여 재시도했으나 다시 결과를 받지 못하고 300초 제한으로 종료됐습니다. PASS나 독립 검증 완료를 주장하지 않습니다. 위 실행 결과는 메인 구현자가 수행한 검사입니다. PR은 이 상태와 실제 서비스 검증 한계를 명시한 초안으로 올리며, 팀의 코드 검토가 필요합니다.
