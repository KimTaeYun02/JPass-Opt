## TEST_GAPS

1. **취소 정리 경로가 실제로 측정되지 않았습니다.** `test_total_timeout_is_mapped_to_safe_504`는 `asyncio.timeout(0)`을 주입하는데, `build_access_day`의 첫 await인 `await asyncio.to_thread(candidates_for_day, day)`는 `try:`/`finally` **바깥**에 있습니다. 즉 데드라인은 walk 태스크가 하나도 생기기 전에 발화하고, `finally`의 `await asyncio.gather(...)`가 만료된 데드라인 안에서 실행되는 상황은 테스트가 통과한 경로가 아닙니다. 결론(`shield` 불필요)에는 동의하지만 — `asyncio.timeout`은 한 번만 취소하므로 내부 재await가 재취소되지 않습니다 — **그 근거로 제시된 테스트는 해당 경로의 증거가 아닙니다.** 보강은 "도보 조회가 진행 중일 때 만료" 1건으로 충분합니다(예: 첫 walk에서 블로킹한 뒤 짧은 타임아웃).
2. **동일 역 + 직접 도보 부재의 2구간 형상 미검증.** `key[0] == key[1]`, `transit["time"] == 0`, `candidate is None`이면 `segments = [walk, walk]`(transit segment 없음, `route == []`)가 생성됩니다. 서버 검증과 프론트 파싱 모두 이 형상을 수용하지만, 백엔드·프론트 어느 쪽에도 단정이 없습니다. INV-3("동일 역도 양수")의 직접 증거이기도 하므로 1건 추가 가치가 높습니다.
3. **`candidateSearchTruncated` 경계값 미고정.** `len(direct_pairs) > MAX_DIRECT_WALKS`의 12/13 경계(정확히 12개일 때 false)가 단정되지 않습니다. 8곳 테스트는 true만 확인합니다.
4. **접근 도보 캐시 재사용 횟수 미고정.** 동일 좌표 장소 2곳이 후보 역 조회·walk 조회를 공유하는지(=예산 상한 논증의 전제)는 `test_coincident_places...`가 간접적으로만 보여줍니다. walk 호출 수 단정이 없습니다.
5. **수동 GUI 검증 미수행.** 자동 승인 심사가 숨은 테스트 서버 기동을 차단해 실행 불가였다는 점은 보고된 그대로 수용합니다. 다만 지도 보행 폴리라인의 시각 확인은 여전히 미완이며, Node 어댑터 → Vite 프록시 → FastAPI 계약 테스트가 이를 부분적으로만 대체합니다.

5. **전 구간 직접 도보 날의 추천 폴백 재검토.** `kind === 'place'` 유입은 계속 차단하되, 역 집합이 비면 `day.stations`(참고 역)로 폴백하는 편이 기능 상실보다 낫습니다. 폴백하지 않기로 유지한다면 사유를 한 줄 남겨주세요.
6. **`Leg.check_segments`의 시각 정합성 검사 위에 dwell 주석.** 프론트에만 있는 "체류시간 도입 시 동시 변경" 메모를 서버에도 남기면 다음 담당자가 두 지점을 동시에 봅니다.

승인 범위 이탈은 없습니다. 버스·추천 API·시간표 재조회는 손대지 않았고, 테스트 중 `Session.request` → `AssertionError`로 실제 공급자 호출이 차단되며 자격증명은 포함되지 않습니다. 공급자 예외가 0으로 대체되지 않는 분기(`transit is None and candidate is None` → 422, 형식 오류 → 502)와, 정상 빈 환승 목록에서 실측 직접 도보를 채택하는 분기가 각각 테스트로 구분되어 있습니다. 투기적 개선(shield, 제네릭화, 대안 역 조합 탐색)은 구현 요구 사항에서 제외하는 것이 맞습니다.
