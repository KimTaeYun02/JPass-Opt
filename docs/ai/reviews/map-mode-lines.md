# 지도 이동 구간 검토·실행 결과

2026-11-09. [설계 계약](../design/map-mode-lines.md)에 따라 Google 지도와 대체 SVG의 이동 구간을 노선 파란 실선·명시적 도보 초록 점선으로 구분했다. API·백엔드·최적 방문 순서 알고리즘은 변경하지 않았다.

## 실행 결과

- `npm --prefix web test`: **148개 통과**.
- `npm --prefix web run build`: 통과.
- `git diff --check`: 오류 없음.
- SDK 대역 검사: 떨어진 단계의 좌표를 잇지 않음, 빈 실제 경로의 관광지 연결선 방지, 단계별 색·반복 심벌, 선택 시 선 재생성·경로 재쓰기·화면 범위 재설정 없음, 경로 축소·재확대 시 선 재사용 및 수단 변경 복원, 입력 전환 시 숨김, fail/destroy 시 전체 선 분리 확인.
- 도보만 있는 범례와 결과 목록의 일치, 동명이역 대신 실제 좌표 끝점 사용, 좌표가 같은 구간에서 점 표시 방지, 한 마커에 경로가 있는 내부 상태의 화면 범위도 검사했다.
- UI·대체 SVG 검사: 서버 단계마다 별도 선, 도보만 점선, 수단명 일부에 ‘도보’가 포함된 다른 노선은 자동 분류하지 않음, 범례·참고선 안내 확인.

## 실제 브라우저

제어된 검색·역 조회·크롤러 응답을 FastAPI로 제공하고 실제 프론트→Vite 프록시→FastAPI→최적화 엔진→Google Maps SDK 흐름을 확인했다. 외부 Gemini·Places·크롤러 호출은 대체했고 Google 지도 표시만 제한된 로컬 지도 키를 사용했다.

3단계 이동에서 파란 실선 2개와 초록 점선 1개가 보이고 결과 목록·지도 범례의 색과 일치했다. 장소 선택 후 선 유지, 입력 단계의 선 숨김, 결과 복귀의 선 복원을 확인했다. 최종 보완 후에도 다시 같은 경로를 계산하고 지도 표시를 확인했다. 브라우저 오류 로그는 없었다.

증빙: Git 제외 경로 `.local-run/map-mode-lines.jpg`. 검증 후 공급자 제어 서버와 테스트 탭은 종료했다. 실서비스의 경로 정확도·실제 Gemini·크롤러·운영 배포를 검증했다는 뜻은 아니다. 현재 선은 각 역 좌표 사이 참고선이며 실제 도로·선로 궤적이 아니다. 관광지↔역 접근 경로는 만들지 않는다.

## Opus 독립 검토

1차와 최종 검토 모두 **VERDICT: PASS / BLOCKERS: None**. 정적 검토에는 최종 코드·설계 계약·테스트 결과를 전달했고, 브라우저 확인은 구현자가 별도로 수행했다.

제안에 따라 예제 선과 범례의 파란색을 맞췄고, 한 마커에 실제 경로가 있는 내부 상태도 화면 범위를 잡도록 보완했다. 동일 좌표 구간을 제거하고, 실제 API 지도 상태에서는 평탄화된 호환 경로를 전달하지 않는다. 선의 재확대·수단 교환 회귀 검사도 보강했다.

남은 비차단 사항: 지도·SVG·CSS의 색 상수가 중복되어 향후 변경 시 함께 맞춰야 한다. 선 풀은 세션 중 최대 구간 수만큼 유지한다. 장소 좌표 편집 기능을 추가한다면 현재 화면 범위 키에 장소 좌표 변화도 포함하도록 검토한다. 현재는 장소 좌표를 직접 편집하지 않는다.
