# 기존 Ekispert 크롤러 버스 검증

후속 검증에서 화면 모드 실조회·정류장 대표 좌표·프론트 재생을 확인했다. 아래는 최초 진단의 기록이며 현재 확인 범위는 [후속 결과](ekispert-bus-live-ui.md)를 함께 참고한다.

2026-11-14. [설계 계약](../design/ekispert-bus-crawler.md)에 따라 기존 크롤러의 검색·추출 기능을 재사용하는 별도 진단과 오프라인 검사를 추가했다.
이 작업에서는 `backend/app/`·`web/`의 제품 코드나 API 명세를 변경하지 않았다. 이전 작업의 미커밋 변경은 유지한다.

## 확인한 사실

- 입력 선택자는 `駅名・バス停名を入力`로 역과 버스정류장 공용이다.
- 자동완성의 첫 결과를 Enter로 선택하므로 정류장·운영사 식별을 보장하지 않는다.
- 기존 추출기는 정류장명·버스 노선명·도보·철도 노선명을 읽는 구조다. 공급자 수단 타입·정류장 고유 ID·좌표는 읽지 않는다.
- [과거 경로 최적화 작업](https://app.notion.com/p/3f76b39941c280709b39fbf09d433548)의 결과 공유에는 `東大農学部前／都営バス`와 `秋葉原駅前／都営バス`를 경유하는 대안이 이미 있다. 새 실조회 결과와 구분한다.
- 제품은 환승 지점 좌표를 HeartRails 철도역 조회로 구하므로, 버스 이름 추출 성공만으로 제품의 버스 이동을 지원할 수 없다.

## 실제 조회

이전 크롤러를 그대로 호출한 1회 진단에서 금각사도 → 기타오지 버스터미널 검색을 시도했다.
일본 출발 시각은 `2026-11-16T09:00:00+09:00`, Chromium은 `headless=True`였다.
요청한 이름은 `金閣寺道`, `北大路バスターミナル`이며 자동완성 검증 전의 입력이다.

홈페이지에서 **HTTP 403**이 반환되어 검색 입력·정류장 선택·노선 추출까지 도달하지 못했다.
이 결과를 확인한 뒤 추가 외부 조회나 접근 차단 우회를 하지 않았다.
공식 Ekispert·Google·Gemini 호출은 0회다. 키를 읽거나 클라우드 설정을 바꾸지 않았다.

이 실조회는 새 CLI 구현 전의 기존 `crawl_route` 호출이었다. 새 CLI의 403·429 종료 처리는 네트워크 차단된 Playwright 응답 대역으로 검증했다.
제품의 `headless=False`/Xvfb 환경이나 다른 서버에서도 반드시 같은 403이 발생한다는 결론은 아니다. 화면 모드 실조회는 이번에 수행하지 않았다.

## 오프라인 검증

합성 fixture에 실제 Playwright DOM 추출기를 적용한 검사와 CLI 검사 **11개 통과**:

- 버스·도보·철도 혼합 노선, 운영사 접미사, 이동 순서와 최종 지점의 null 노선 보존
- 대안 경로 순서 유지, 미확인 시간·운임을 null로 유지
- 주변 설명의 도보 문구보다 명시된 노선명 우선
- 잘못된 지점/구간 교대 구조와 다른 운영사 이름을 성공 단서로 처리하지 않음
- 기본·잘못된 입력은 브라우저를 열지 않음, 예외 원문 비노출
- 403·429에서 검색 시도 한 번으로 중단
- 부가 이미지의 403·429를 정상 문서의 차단으로 오분류하지 않음
- 제한 시간 초과 시 검색 작업 취소와 실제 Chromium 페이지 종료

합성 HTML은 현재 사이트 응답이 아니다. 현재 버스 운행·자동완성 성공·공식 수단 분류는 미검증이다.
재현 명령과 결과 상태는 [실행 안내](../../../backend/docs/ekispert-bus-crawler.md)에 있다.

백엔드 계약 검사 전체 **66개 통과**. 새 두 Python 파일의 Ruff 검사·포맷 검사와 `git diff --check`도 통과했다.
프론트 파일은 수정하지 않아 이번에는 프론트 검사·브라우저 QA를 반복하지 않았다.

## 후속 조건

먼저 정상 접근 가능한 실행 환경에서 운영사 포함 정류장 두 곳을 확인하고 한 구간을 조회해야 한다.
그다음 버스정류장의 고유 식별·좌표 공급원을 결정한다. HeartRails 철도역 좌표로 대신하거나 노선명만으로 확정 수단을 만들지 않는다.
이 두 조건이 갖춰지면 구간별 수단·소요시간·좌표를 API·프론트에 연결한다.

## 독립 검토

Claude Opus 설계 계약을 받은 뒤 구현했다. 1차 독립 검토에서 부가 리소스의 403·429를 문서 차단으로 오분류할 수 있다는 지적을 받아 주 프레임 문서로 판정 범위를 좁혔다.
부가 리소스 오류와 시간 초과 정리 검사를 추가했다. 실제 홈페이지 403은 새 CLI가 아니라 기존 크롤러의 최초 페이지 응답에서 관측한 값이다.
새 CLI의 차단 처리는 검색 함수를 응답 대역으로 바꾼 검사이며 실제 사이트의 전체 검색 흐름까지 검증한 것은 아니다.
최종 재검토는 **VERDICT: PASS / BLOCKERS: 없음**이다. 검토에는 설계 계약·최종 소스·66개 검사 결과·실조회 제한을 제공했다. 검토 모델이 테스트를 직접 실행한 것은 아니다.
추가로 지적된 테스트 보강 후보는 빈 결과·iframe 차단·stdout 출력 억제 직접 검사다. 제품의 화면 모드 실조회와 현재 버스 지원은 여전히 미검증이다.
