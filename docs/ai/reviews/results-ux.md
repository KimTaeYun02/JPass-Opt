# 동선 결과 UI 검토·실행 결과

2026-11-09. [설계 계약](../design/results-ux.md)에 따라 일본 여행 초보자가 역 간 결과를 읽을 수 있도록 표시를 개선했다. API·백엔드 알고리즘·외곽 화면 크기는 변경하지 않았다.

## 구현·검증

- 관광지→역 접근 정보 미제공→응답의 역·노선 순서→관광지 접근 정보 미제공 순서로 표시한다. 단계는 기본 표시하며 응답의 `도보`만 별도 배지로 구분한다.
- 시간 칩은 누적 역 간 이동이며 서버 시각은 참고 시각으로 구별한다. 교통비 합계도 역 간 기준으로 표시한다.
- 같은 역 0분은 관광지 사이 실제 이동이 없다는 뜻으로 표시하지 않는다. 같은 역에 0이 아닌 값이 오면 값을 유지하고 확인을 안내한다.
- 프론트 자동 검사: `npm --prefix web test` **141개 통과**. 누락 정보·동명이역·같은 역·여러 구간 누적·하루 한 장소·일본 날짜 변경·예제 출처·이스케이프·지도 포커스 계약을 포함한다.
- 빌드: `npm --prefix web run build` 통과.
- 브라우저 예제 모드: 결과 생성, 장소 선택 시 지도 상세 표시, 2일차 전환, 선택적 추천 펼치기, 추천 추가 후 이전 결과·대기 목록·대기 마커 유지 확인.
- 실제 HTTP 경유 브라우저 검사: 프론트→Vite 프록시→FastAPI→기존 최적화 엔진을 사용하고 검색·역·크롤러 공급자 응답만 제어했다. 관광지 두 곳 추가→선택 단계→최적화→철도명/명시적 도보/버스명 3단계 표시와 23분·300엔을 확인했다. 버스명은 임의로 버스 유형 배지로 변환하지 않는다.
- 해당 브라우저의 오류 로그는 없었다. 1280px에서 문서 가로 초과가 없고 상세 단계 폭도 넘치지 않았다. 사용자 제외 항목인 여백 문제를 재현·수정한 것으로 간주하지 않는다.
- 공급자 제어 서버는 검증 후 종료했다. Google Maps는 로컬 제한 키로 표시했다. Gemini 실제 호출·실제 크롤러 경로의 정확도·운영 배포는 이번 검증 범위에 포함하지 않았다.
- 화면 증빙은 Git 제외 경로 `.local-run/results-ux-controlled.jpg`, `.local-run/results-ux-example.jpg`에 저장했다.

## Opus 독립 검토

1차 `VERDICT: PASS`, `BLOCKERS: None`. Claude는 전달한 코드·diff·설계·실행 결과를 정적으로 검토했으며 테스트를 직접 실행하지 않았다.

주요 제안 중 같은 역/비정상 비용 응답 안내, 여러 관광지 누적 시간·특수문자 ID 검사, 의미 없는 화살표 ARIA 속성 제거, 미사용 상세 CSS·중복 규칙 정리를 반영했다. 최종 수정 후 2차 검토도 `VERDICT: PASS`, `BLOCKERS: None`이었다. 권고된 `.sr-only` 스타일은 기존 `demo.css`에 있고 실제 브라우저에서도 접두 문구가 시각적으로 숨겨진 것을 확인했다.

검토에서 제기한 역 좌표·장소 ID·구간 순서·합계의 유효성은 기존 `demo-api.ts` 파서가 검증한다. 렌더러에서 별도 보정하지 않는다. 접근 이동수단·버스/지하철 종류·단계별 시간·환승 횟수를 안정적으로 표시하려면 별도 API 계약 확장이 필요하다.

## 후속 색상 피드백

사용자 피드백으로 결과의 노선 이동 행에는 파란 배경·실선, 명시적 도보 행에는 초록 배경·점선을 적용했다. 글자 배지도 유지한다. 정보가 없는 접근 구간을 도보로 분류하지 않는다. CSS만 수정했고 빌드가 통과했다. 제어된 API 결과의 실제 브라우저 계산 스타일에서 서로 다른 배경색과 실선/점선을 확인했고 행 가로 넘침은 없었다. 증빙은 `.local-run/route-mode-colors.jpg`다. 이번 소규모 색상 변경에는 추가 Opus 검토를 수행하지 않았다.
