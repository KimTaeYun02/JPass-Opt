# 기준역 API 및 프론트 통합 검증

2026-11-05, 최신 병합된 `main`(`478e697`)을 `feat/frontend-demo`에 통합해 검증했다. 팀원의 기존 경로 서비스·외부 클라이언트·최적화 엔진은 변경하지 않았다. [설계 계약](../design/station-integration.md)을 기준으로 한다.

## 실행한 검사

- `web/npm test`: 128개 통과, 실패·건너뜀 0. 기존 116개와 기준역·추천·최신 검색 계약 검사 12개를 포함한다. 런처 경로·환경 복원·오프라인 보고서 경로도 검사한다.
- `web/npm run build`: TypeScript·Vite 성공. 두 HTML 진입점 생성.
- `backend/python -m unittest discover -s contract_checks -v`: 10개 통과. 기준역 ID 대응·공유 역·요청별 좌표 재사용·최대 7일×8곳·입력 거절·부분 실패와 실제 기존 HeartRails 클라이언트 매핑, OpenAPI 스냅샷 일치를 검사한다.
- 통합 검사: 실제 프론트 HTTP 어댑터→실제 Vite 프록시→실제 FastAPI 라우터·서비스→실제 최적화 엔진을 실행했다. 검색·기준역·초기 추천·최적화·결과 Nearby·모호한 검색 응답을 검사했다. 최적 경로 B→A, 9분·180엔은 제어된 구간 행렬로 계산한 결과다.
- Chromium: 실제 Vite 프록시와 FastAPI를 사용해 장소 검색→선택→기준역 및 통합 추천→추가 선택→계산→결과 표시를 확인했다. 1366×768·1920×1080에서 수평 넘침·페이지 오류 0. 타이핑·초기 진입 시 API 호출 0. 한글 composition 이벤트 시 입력 요소가 유지되는 것을 확인했다.
- 위 통합·브라우저 검사는 외부 LLM·Google·HeartRails·크롤러만 대체했다. 예상하지 못한 외부 호출은 차단했고 발생하지 않았다. Maps SDK는 의도적으로 차단해 SVG 대체 지도를 사용했다. 실제 키나 유료 API를 호출하지 않았다.
- 신규 Python 코드의 Ruff lint·format 검사 통과. OpenAPI 스냅샷 일치는 자동 검사에 포함했다.

## 배포 후 남은 확인

백엔드는 아직 배포되지 않았다. 실제 배포 주소·CORS/프록시·TLS·서버 API 키 유효성·공급자 응답·지도 SDK·실제 크롤링 결과는 검증하지 않았다. 팀원이 이 브랜치의 기준역 API가 포함된 서버를 배포한 뒤 `/openapi.json`에서 네 경로를 확인하고, 검색→추천→계산 전체 흐름을 추가 확인해야 한다. 프론트에는 서버 키를 복사하지 않는다.

기준역 조회는 최대 56개 좌표를 순차 조회하고 전체 deadline이 없으므로 느린 공급자는 대기 시간을 늘릴 수 있다. 프론트는 한 일차(최대 8곳)만 요청한다. 클라이언트 취소가 이미 시작된 서버 측 작업을 즉시 중단시키지는 않는다.

## 독립 검토

Claude Opus의 최종 diff 검토와 후속 변경 재검토가 모두 `PASS`, 차단 이슈 없음으로 끝났다. 역이 없는 경우와 조회 실패의 안내를 구분하고, 기준역의 선택적 노선 정보를 Nearby에 전달하도록 보완한 뒤 프론트 128개·백엔드 10개 검사와 빌드를 다시 통과했다.

두 검토 모두 실제 배포·Maps SDK·공급자 응답을 검증한 것은 아니다. 기준역 조회의 순차 처리, 요청 전체 deadline 부재, 중복 렌더 경로의 버튼 문구 유지보수 등은 비차단 위험으로 남는다. 모든 코드 검증 후 기존 PR 브랜치를 갱신하며 배포 후 확인이 끝날 때까지 초안 상태를 유지한다.
